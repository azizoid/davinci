# Specification Index

These documents define the behavior of the future system. If documents conflict, the product specification establishes the user promise, the media policy governs legal use, and the editing rules govern creative choices.

- [`product-specification.md`](product-specification.md): product goals, scope, requirements, and success criteria.
- [`editing-rules.md`](editing-rules.md): default editorial judgment and quality bar.
- [`media-licensing-policy.md`](media-licensing-policy.md): allowed media sources, provenance, and licensing controls.
- [`autonomous-workflow.md`](autonomous-workflow.md): end-to-end orchestration and failure behavior.
- [`analysis-and-edit-plan.md`](analysis-and-edit-plan.md): timestamped observations, AI decisions, frame/sample coordinates, and Resolve operation planning.
- [`project-artifact-structure.md`](project-artifact-structure.md): canonical files and directories for a job.
- [`runtime-deployment.md`](runtime-deployment.md): one-button control panel, Docker boundary, Resolve host integration, and path/security rules.
- [`implementation-decisions.md`](implementation-decisions.md): architectural decisions already made.
- [`open-questions.md`](open-questions.md): decisions that must be resolved during implementation.

## Normative Language

`MUST`, `MUST NOT`, `SHOULD`, `SHOULD NOT`, and `MAY` indicate requirement strength. Requirements apply to the eventual implementation, not to this specification-only scaffold.
